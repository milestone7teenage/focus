# ARCHITECTURE — focus

Версия 0.3. Архитектура утверждена. Все открытые решения закрыты. Реализация запрещена до старта Этапа 1 из ROADMAP.md.

## Стек
iOS 17+, Swift, SwiftUI, SwiftData, UserNotifications, Foundation Calendar/DateComponents.

## Компоненты
- `App`: точка входа, ModelContainer, регистрация обработчика уведомлений, внедрение зависимостей.
- `Features`: `OneTimeTasks`, `RecurringTasks`, `TaskEditor`, `TaskCard`, `UndoBanner`.
- `Domain`: состояния, правила выполнения/удаления/snooze, календарные политики.
- `Data`: SwiftData-модели и репозитории.
- `Services`: `TaskManager`, `ScheduleEngine`, `NotificationScheduler`, `NotificationActionHandler`, `AppLifecycleCoordinator`.
- `Design`: системные цвета, типографика, карточки, доступность.
- `Tests`: unit- и integration-тесты.

## Модели SwiftData

### OneTimeTask
- `id: UUID`
- `title: String`
- `scheduledAt: Date`
- `state: ReminderState` (`pending`/`seen`)
- `createdAt: Date`
- `repeatCount: Int`
- `notificationGeneration: Int`

При Snooze разовой задачи напрямую обновлять `scheduledAt = now + 30 минут` и сбрасывать состояние в `pending`. Поле `snoozedUntil` в `OneTimeTask` отсутствует — оно есть только в `DailyTaskInstance`.

### RegularTaskTemplate
- `id: UUID`
- `title: String`
- `localHour: Int`
- `localMinute: Int`
- `isEnabled: Bool`
- `createdAt: Date`
- `notificationGeneration: Int`

### DailyTaskInstance
- `id: UUID`
- связь с `RegularTaskTemplate`
- `dayKey` — локальная календарная дата
- `state: ReminderState`
- `repeatCount: Int`
- `snoozedUntil: Date?`
- `notificationGeneration: Int`

Для одного шаблона допускается не более одного активного экземпляра на текущий локальный день. Выполнение удаляет дневной экземпляр, но сохраняет шаблон. История не создаётся.

### ReminderState
`pending` и `seen`. `completed`/`deleted` — действия, а не архивные состояния. После них активная запись удаляется.

## dayKey
Строка формата `YYYY-MM-DD` в локальном часовом поясе устройства. Вычисляется строго через `Calendar.current`.

## Undo
Удаление: запись сразу удаляется из SwiftData, уведомления отменяются. В памяти хранится DTO-снимок удалённой задачи на 3 секунды. По истечении 3 секунд снимок уничтожается, задача считается окончательно удалённой.

Если приложение свернуто или закрыто в течение этих 3 секунд — снимок уничтожается немедленно и задача считается окончательно удалённой. Undo невозможен.

При Undo восстанавливаются задача/шаблон, дневной экземпляр и уведомления.

## ScheduleEngine
Чистый доменный компонент без SwiftUI, SwiftData и UserNotifications. Отвечает за локальный день, `dayKey`, ежедневное расписание, reset, DST, смену часового пояса и перенос прошедшего сегодняшнего времени на завтра.

Reset:
1. определить текущую локальную календарную дату;
2. найти устаревшие дневные экземпляры;
3. отменить их уведомления;
4. удалить экземпляры без истории;
5. обеспечить по одному текущему экземпляру для каждого активного шаблона;
6. не создавать дубликаты;
7. передать актуальные напоминания планировщику.

Reset должен быть идемпотентным. Не прибавлять 86 400 секунд для перехода на следующий календарный день.

## NotificationScheduler
Адаптер над `UNUserNotificationCenter`. Отвечает за разрешения, создание/отмену запросов, уникальные идентификаторы, получение ожидающих запросов, сверку с активными задачами и системный бюджет.

Цикл: T0, T+10, T+20, T+30 минут. Идентификатор должен позволять определить тип сущности, UUID, dayKey для регулярного экземпляра, поколение расписания и номер повтора.

Планирование:
1. получить активные напоминания;
2. вычислить ближайшее время;
3. отсортировать по срочности;
4. учесть уже ожидающие запросы;
5. использовать только доступные слоты;
6. не удалять задачи при нехватке слотов;
7. повторять сверку при изменении задач, разрешений и жизненного цикла.

Не считать число 64 безусловной гарантией для всех будущих версий iOS. Численный лимит и поведение целевой iOS перепроверить по актуальной документации и на устройстве.

### Бюджет уведомлений
Безопасный лимит — до 60 ожидающих запросов из 64 системных слотов. Активные задачи сортируются по ближайшему времени следующего уведомления; самые ближайшие получают приоритет при планировании.

### Snooze
`now + 30 минут`; отменить старый цикл; увеличить поколение расписания; вернуть текущий экземпляр в PENDING; запланировать новый цикл. Для регулярной задачи изменяется только дневной экземпляр, не шаблон.

Если snooze регулярной задачи пересекает полночь: reset нового дня имеет безусловный приоритет. Вчерашний snooze сгорает и не переносится на следующий день.

### SEEN
При действии «Увидел» или открытии по телу уведомления:
- найти активную сущность;
- установить SEEN;
- отменить оставшиеся повторы;
- сохранить состояние;
- повторную обработку сделать идемпотентной.

Если сущность уже удалена, устаревшее действие игнорируется и не восстанавливает её.

## NotificationActionHandler
Обрабатывает custom action «Увидел», открытие по уведомлению и устаревшие действия. Открытие по телу уведомления должно переводить связанную активную задачу в SEEN. Сохранение должно быть завершено до подтверждения обработки системного события.

## AppLifecycleCoordinator
При запуске и возвращении в active:
- загрузить данные;
- определить локальный день;
- выполнить reset;
- проверить разрешения;
- получить ожидающие уведомления;
- отменить устаревшие запросы;
- восстановить недостающие в пределах бюджета;
- обновить UI.

Не рассчитывать на запуск приложения ровно в полночь или постоянную фоновую работу.

## TaskCard
Карточка задачи поддерживает три основных жеста:
- Long Press ~0,6 секунды — выполнение задачи с плавным прогрессом и тактильным откликом.
- Свайп влево — удаление с Undo на 3 секунды.
- Свайп вправо — snooze на 30 минут.

Жест выполнения (Long Press) не блокирует вертикальный скролл списка и горизонтальные свайпы. При смещении пальца во время нажатия прогресс отменяется и пользователю доступны скролл/свайпы.

### Accessibility-альтернативы
На карточке задачи обязательно предусмотрены стандартные `.accessibilityAction` для:
- «Выполнить»
- «Отложить на 30 мин»
- «Удалить»

## Тесты

### ScheduleEngine
- reset и идемпотентность;
- один экземпляр на шаблон/день;
- несколько шаблонов;
- переходы DST;
- смена часового пояса;
- перенос прошедшего времени сегодня на завтра;
- будущее время не переносится.

### TaskManager
- создание разовой и регулярной задачи;
- выполнение/удаление;
- выполнение дневного экземпляра без удаления шаблона;
- snooze меняет только текущий экземпляр;
- Undo обоих типов;
- сохранение SEEN;
- повторная обработка SEEN.

### NotificationScheduler
Использовать fake-адаптер центра уведомлений:
- четыре запроса на цикл;
- интервалы 0/10/20/30;
- уникальные ID;
- отсутствие дубликатов;
- отмена после SEEN/выполнения/удаления;
- новый цикл после snooze;
- бюджет и нехватка слотов;
- восстановление;
- игнорирование старого поколения.

### UI/integration
Две вкладки, формы, длинные названия, Dynamic Type, системные темы, long press, swipe delete + Undo, swipe snooze, открытие уведомления, отказ в разрешениях, восстановление после перезапуска.
